# Referência de Comandos

Este documento serve como a **Fonte Única de Verdade** (Single Source of Truth) para cada comando CLI, script PNPM, comando de container e instrução de orquestração utilizada no monorepo %PROJECT_DOMAIN%.

## Orquestração do Monorepo

Scripts usados para gerenciar dependências, limpeza e tarefas em todo o workspace.

- **`pnpm install`**: Instala todas as dependências no monorepo.
- **`pnpm install --frozen-lockfile`**: Instala as dependências estritamente a partir do `pnpm-lock.yaml` (usado em CI/CD).
- **`pnpm project:clear`**: Limpa todos os diretórios `node_modules` e caches de build usando o `npkill`.

### Gerenciamento de Dependências (Catalogs)

Todas as novas dependências devem ser adicionadas a um catálogo (seja o catálogo padrão ou um específico) para garantir a consistência de versão em todo o monorepo.

**Adicionando ao Workspace Raiz:**
Adicionar uma dependência ao `package.json` raiz requer a flag `-w` (ou `--ignore-workspace-root-check`).

- **`pnpm add <package> -w --save-catalog`**: Adiciona um pacote à raiz e salva sua versão no catálogo padrão.
- **`pnpm add <package> -w --save-catalog-name <catalog_name>`**: Adiciona um pacote à raiz e salva sua versão em um catálogo específico.

**Adicionando a um Workspace Específico:**
Use a flag `--filter` para direcionar a um pacote de workspace específico.

- **`pnpm add <package> --filter <workspace> --save-catalog`**: Adiciona um pacote a um workspace e salva sua versão no catálogo padrão.
- **`pnpm add <package> --filter <workspace> --save-catalog-name <catalog_name>`**: Adiciona um pacote a um workspace e salva sua versão em um catálogo específico.

**Usando um Pacote já Definido no Catálogo:**

- **`pnpm add <package>@catalog: --filter <workspace>`**: Instala um pacote que já está definido no catálogo padrão em um workspace específico.

## Validação e Qualidade

Scripts para garantir a qualidade do código e a segurança de tipos.

- **`pnpm typecheck`**: Executa a validação do TypeScript em paralelo em todos os workspaces via Turborepo.
- **`pnpm lint`**: Executa a validação do ESLint em todos os workspaces.
- **`pnpm build`**: Compila um build de produção para todas as aplicações e pacotes.
- **`pnpm format:check`**: Verifica a formatação em todo o monorepo.
- **`pnpm format:write`**: Corrige automaticamente problemas de formatação em todos os arquivos.

## Gerenciamento de Cluster Kubernetes (Minikube)

Comandos para controlar o cluster Kubernetes de desenvolvimento local.

- **`pnpm minikube:up`**: Inicia o cluster Minikube local usando o driver do Podman e configura a montagem automática do diretório do projeto.
- **`pnpm minikube:tunnel`**: Inicia o túnel de rede do Minikube para resolver alocações de IP do tipo LoadBalancer.
- **`pnpm minikube:status`**: Verifica o status do cluster Minikube local.
- **`pnpm minikube:mount`**: Monta o diretório de workspace do projeto dentro do nó do Minikube.

## Implantações no Kubernetes (Skaffold)

Comandos para build, deploy e hot-reload de componentes dentro do cluster Kubernetes.

- **`pnpm k8s:dev`**: Implanta a stack completa (cortex, platform, studio) no cluster com o hot-reloading ativado.
- **`pnpm k8s:up`**: Executa um build e implantação única da stack completa no cluster.
- **`pnpm k8s:down`**: Exclui todos os recursos implantados do cluster.
- **`pnpm platform:dev`**: Implanta apenas os serviços de plataforma com hot-reloading.
- **`pnpm platform:down`**: Exclui os serviços de plataforma do cluster.
- **`pnpm cortex:dev`**: Implanta apenas os serviços de IA do Cortex no cluster com hot-reloading.
- **`pnpm cortex:clean`**: Exclui os serviços do Cortex do cluster.
- **`pnpm cortex:stop`**: Remove as instâncias do Kubernetes e do Podman Compose para o Cortex.

## Developer Hub

Comandos para o contexto delimitado do Developer Hub (`hub/`).

- **`pnpm hub:dev`**: Inicia os servidores de desenvolvimento local (API na porta 3006 e Web na porta 5173).
- **`pnpm hub:up`**: Inicia a infraestrutura de suporte local (MongoDB) via Podman Compose.
- **`pnpm hub:down`**: Para a infraestrutura local.
- **`pnpm hub:reset`**: Exclui os volumes persistentes do banco de dados e reinicia a infraestrutura do Hub.
- **`pnpm hub:staging`**: Inicia o ambiente de staging do Hub usando o perfil de compose correspondente.
- **`pnpm hub:prod`**: Inicia o ambiente de produção do Hub.
- **`pnpm hub:staging:down`**: Para a stack de staging do Hub.
- **`pnpm hub:prod:down`**: Para a stack de produção do Hub.

## Cortex (Modo Podman Compose)

Comandos para rodar a stack de IA do Cortex localmente via Podman Compose.

- **`pnpm cortex:up`**: Inicia os serviços do Cortex (gateway, guardrails, memory API e serviços MCP) via Podman Compose.
- **`pnpm cortex:down`**: Para os containers do Cortex e limpa pontes de rede órfãs.
- **`pnpm cortex:reset`**: Para e reinicia o ambiente do Cortex Compose.
- **`pnpm cortex:logs`**: Transmite os logs em tempo real dos containers do Cortex.

## Studio e Renderer

Comandos para geração de assets, design systems e renderização.

- **`pnpm studio:dev`**: Implanta o workspace do Studio no Kubernetes via Skaffold.
- **`pnpm studio:down`**: Exclui a implantação do Studio do cluster.
- **`pnpm studio:bucket`**: Sincroniza os assets visuais do bucket Cloudflare R2.
- **`pnpm renderer:clean`**: Limpa os assets compilados no workspace do renderer.
- **`pnpm renderer:generate`**: Recompila componentes dinâmicos do perfil e templates do README.

## Documentação

Comandos para o Docusaurus Knowledge Base (`docs/`).

- **`pnpm docs:dev`**: Inicia o servidor local de desenvolvimento do Docusaurus em inglês (porta 3002) com HMR.
- **`pnpm docs:dev:pt`**: Inicia o servidor do Docusaurus em português do Brasil (`pt-BR`).
- **`pnpm docs:build`**: Compila a documentação em HTML/CSS estáticos para produção.
- **`pnpm docs:preview`**: Compila e serve uma pré-visualização de produção da documentação.
- **`pnpm docs:down`**: Encerra o servidor de documentação na porta correspondente.

## Git e Controle de Versão

Fluxos de trabalho para ramificação (branching), commit e releases.

- **`git flow feature start <name>`**: Inicia uma nova ramificação de feature a partir de `develop`.
- **`git push -u origin feature/<name>`**: Envia uma ramificação de feature para o repositório remoto.
- **`gh pr create --base develop --fill --web`**: Cria um Pull Request direcionado à ramificação `develop`.
- **`gh pr merge --squash --delete-branch`**: Mescla um PR usando a estratégia de squash-and-merge.
- **`git flow hotfix start <name>`** / **`git flow hotfix finish <name>`**: Gerencia correções de emergência contra a ramificação `main`.
- **`pnpm version:changeset`**: Gera um arquivo de changeset para rastrear incrementos de versão e logs de alteração.
- **`pnpm version:bump`**: Atualiza a versão dos pacotes com base nos changesets.
- **`pnpm version:publish`**: Publica todos os pacotes atualizados nos registros.
