# Configuração do Desenvolvimento Local

Neste tutorial, configuraremos o monorepo tupynambalucas.dev na sua máquina local. Ao final desta lição, você terá o ambiente de desenvolvimento completo rodando e pronto para você construir novas funcionalidades.

## Pré-requisitos

Antes de começarmos, garanta que você possui os seguintes itens instalados:

- Node.js versão 22
- PNPM versão 11
- Podman Desktop + Podman CLI + Extensão Compose (em vez de Docker)
- Minikube e kubectl (para o modo cluster Kubernetes)
- Skaffold (para pipelines de implantação do Kubernetes e recarregamento dinâmico/hot-reload)
- Git

---

## Passo 1: Clonar o Repositório

Primeiro, clone o repositório em seu workspace local e navegue para dentro dele.

```bash
git clone https://github.com/tupynambalucas/tupynambalucas.git
cd tupynambalucas
```

Você deve ver uma estrutura de diretórios contendo pastas como `docs`, `hub`, `cortex`, `profile`, `studio`, `platform` e `tools`.

---

## Passo 2: Instalar Dependências

Em seguida, instale as dependências do projeto. Como este é um monorepo, usamos o PNPM para instalar tudo de uma vez.

Execute o seguinte comando:

```bash
pnpm install
```

Quando o comando for finalizado, você verá uma saída confirmando que as dependências foram vinculadas ao content-addressable store.

---

## Passo 3: Configurar Variáveis de Ambiente

Cada workspace gerencia suas próprias configurações locais. Copie os arquivos de modelo `.env.example` para criar os arquivos de ambiente ativos:

```bash
# Configura as variáveis de ambiente do Cortex
cp cortex/infrastructure/.env.example cortex/infrastructure/.env

# Configura as variáveis de ambiente do Hub
cp hub/infrastructure/docker/.env.example hub/infrastructure/docker/.env.dev
```

:::info[Abra e Edite a Configuração]
Abra os arquivos `.env` recém-criados e adicione os tokens necessários (como `GITHUB_PERSONAL_ACCESS_TOKEN`, `FIRECRAWL_API_KEY`) para acessar os serviços de nuvem.
:::

---

## Passo 4: Configurar a Máquina Podman

Antes de iniciar qualquer carga de trabalho de container, inicialize e inicie a máquina Podman padrão:

```bash
podman machine init
podman machine start
```

Verifique se a engine de container está ativa:

```bash
podman info
```

---

## Passo 5: Iniciar a Infraestrutura

Você pode escolher entre duas pipelines de orquestração de acordo com sua tarefa atual:

### Opção A: Modo Podman Compose (Desenvolvimento Local Rápido)

Esta é a abordagem recomendada para iterações rápidas, codificação de frontend e depuração de microserviços.

1. **Iniciar Infraestrutura de Suporte**:
   ```bash
   pnpm cortex:up
   ```
2. **Iniciar Servidor de Desenvolvimento**:
   ```bash
   pnpm hub:dev
   ```

Acesse `http://localhost:5173` para a interface do Hub e `http://localhost:3002` para o site de documentação.

### Opção B: Modo Kubernetes (Skaffold + Minikube)

Esta abordagem é necessária para testar manifestos Kubernetes, controllers de ingress, configurações de telemetria ou integrações de serviços.

1. **Iniciar o Cluster Minikube**:
   ```bash
   pnpm minikube:up
   ```
2. **Iniciar o Túnel de Rede** (em um terminal separado):
   ```bash
   pnpm minikube:tunnel
   ```
3. **Implantar com Skaffold em Modo Dev (Hot-Reloading)**:
   ```bash
   pnpm k8s:dev
   ```

O Skaffold fará o build de suas imagens, implantará os manifestos, transmitirá os logs dos containers e direcionará portas de serviços automaticamente para a sua máquina local (como o `agentgateway` em `http://localhost:8080/mcp/http`).

:::tip[Orquestração Avançada]
Para detalhes aprofundados sobre a configuração de extensões do Podman Desktop, túneis de rede do Minikube, redirecionamento de portas com Skaffold e resolução de variáveis de ambiente, consulte o [Guia de Configuração da Orquestração Local](/docs/guides/orchestration-environment).
:::

## Conclusão

Parabéns! Você clonou com sucesso o repositório, configurou as variáveis de ambiente, iniciou o Podman e lançou o servidor de desenvolvimento local. Agora você está totalmente equipado para começar a construir e contribuir com o projeto.
