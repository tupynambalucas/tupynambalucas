# Local Development Setup

In this tutorial, we will set up the tupynambalucas.dev monorepo on your local machine. By the end of this lesson, you will have the complete development environment running and ready for you to build features.

## Prerequisites

Before we begin, ensure you have the following installed:

- Node.js version 22
- PNPM version 11
- Podman Desktop + Podman CLI + Compose Extension (instead of Docker)
- Minikube and kubectl (for Kubernetes cluster mode)
- Skaffold (for Kubernetes deployment pipelines and hot-reloading)
- Git

---

## Step 1: Clone the Repository

First, clone the repository to your local workspace and navigate into it.

```bash
git clone https://github.com/tupynambalucas/tupynambalucas.git
cd tupynambalucas
```

You should see a directory structure containing folders like `docs`, `hub`, `cortex`, `profile`, `studio`, `platform`, and `tools`.

---

## Step 2: Install Dependencies

Next, install the project dependencies. Since this is a monorepo, we use PNPM to install everything at once.

Run the following command:

```bash
pnpm install
```

When it finishes, you will see output confirming dependencies are linked to the content-addressable store.

---

## Step 3: Configure Environment Variables

Each workspace manages its own local configuration. Copy the template `.env.example` files to create the active environment files:

```bash
# Set up Cortex environment variables
cp cortex/infrastructure/.env.example cortex/infrastructure/.env

# Set up Hub environment variables
cp hub/infrastructure/docker/.env.example hub/infrastructure/docker/.env.dev
```

:::info[Open and Edit Configuration]
Open the newly created `.env` files and add any required tokens (e.g., `GITHUB_PERSONAL_ACCESS_TOKEN`, `FIRECRAWL_API_KEY`) to access cloud services.
:::

---

## Step 4: Configure Podman Machine

Before starting any container workloads, initialize and start the default Podman machine:

```bash
podman machine init
podman machine start
```

Verify that the container engine is active:

```bash
podman info
```

---

## Step 5: Start the Infrastructure

You can choose between two orchestration pipelines based on your current task:

### Option A: Podman Compose Mode (Fast Local Development)

This is the recommended approach for rapid iteration, frontend coding, and microservice debugging.

1. **Start Backing Infrastructure**:
   ```bash
   pnpm cortex:up
   ```
2. **Start Development Server**:
   ```bash
   pnpm hub:dev
   ```

Navigate to `http://localhost:5173` to access the Hub interface, and `http://localhost:3002` for the documentation site.

### Option B: Kubernetes Mode (Skaffold + Minikube)

This approach is required for testing Kubernetes manifests, ingress controllers, telemetry configs, or service integrations.

1. **Start the Minikube Cluster**:
   ```bash
   pnpm minikube:up
   ```
2. **Start the Network Tunnel** (in a separate terminal):
   ```bash
   pnpm minikube:tunnel
   ```
3. **Deploy with Skaffold Dev Mode (Hot-Reloading)**:
   ```bash
   pnpm k8s:dev
   ```

Skaffold will build your images, deploy the manifests, stream container logs, and automatically port-forward services to your local machine (e.g., `agentgateway` to `http://localhost:8080/mcp/http`).

---

## Conclusion

Congratulations! You have successfully cloned the repository, configured environment variables, started Podman, and launched the local development server. You are now fully equipped to start building and contributing to the project.
