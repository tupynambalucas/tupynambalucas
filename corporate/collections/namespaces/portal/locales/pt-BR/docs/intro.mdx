# %PROJECT_DOMAIN% Monorepo

Este repositório é um monorepo que contém um gerador de estatísticas de perfil de desenvolvedor, site/hub pessoal, ferramentas de desenvolvedor, design tokens e documentação.

---

## 1. Visão Geral do Produto e Proposta de Valor

O monorepo coordena o site pessoal do desenvolvedor (`hub`), visualizações de estatísticas automatizadas (`renderer`), sistemas de design (`studio`), hub de processamento de IA (`cortex`) e ferramentas de automação (`tools`).

A principal aplicação voltada para o cliente é o **Developer Hub** (`@repo/hub/*`):

| Para Visitantes                                                                           | Para o Desenvolvedor (Admin)                                                     |
| :---------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------- |
| **Portfólio**: Visualize projetos, arquiteturas de código e destaques.                    | **Publicação de Blog**: Publique artigos técnicos e estudos de caso.             |
| **Formulário de Contato**: Envie mensagens ou consultas de consultoria com segurança.     | **Coleta de Leads**: Gerencie submissões e dados do painel.                      |
| **Catálogo de Serviços**: Solicite serviços de desenvolvimento de software personalizado. | **Automação de Perfil**: Atualize automaticamente as métricas do GitHub via Zig. |

---

## 2. Fluxo Operacional

O site de portfólio e o gerador de estatísticas operam em um workflow simplificado:

1. **Apresentação do Portfólio**: Os visitantes exploram o frontend `@repo/hub/web`, consumindo postagens de blog e destaques de projetos servidos por `@repo/hub/api`.
2. **Envio de Contato**: As entradas do formulário são validadas por meio de chaves anti-spam do Turnstile, serializadas usando esquemas Zod de `@repo/hub/core` e persistidas em uma instância do MongoDB.
3. **Geração de Estatísticas do Renderer**: O workspace `@/renderer` compila as métricas do GitHub usando uma CLI nativa em Zig e sobrescreve dinamicamente o arquivo `README.md` raiz.

---

## 3. Estratégia de Hospedagem e Deploy

O monorepo utiliza o Cloudflare e ambientes de VPS padrão para operação de zero manutenção e alto desempenho.

### Infraestrutura e Hospedagem

- **Cloudflare Pages**: O hub de documentação do Docusaurus (`docs/`) e o frontend de SPA React do desenvolvedor (`hub/services/web`) são deployed para o Cloudflare Pages para entrega otimizada via CDN.
- **Hetzner Cloud VPS / Linux VPS**: A REST API do backend Fastify (`hub/services/api`) e as pilhas do compose do MongoDB/Redis são executadas em uma instância de VPS leve.
- **DNS & SSL**: O roteamento de DNS e a proteção de proxy são gerenciados globalmente por meio do Cloudflare.

## 6. Início Rápido

Certifique-se de ter **Node.js 22+**, **PNPM 11+**, **Zig**, **Podman** (com a extensão Compose), **Minikube** e **Skaffold** instalados.

1. **Instale as Dependências:**

   ```bash
   pnpm install
   ```

2. **Configure os Arquivos de Ambiente:**
   Cada workspace e serviço possui seu próprio arquivo de ambiente. Copie os modelos de exemplo e adicione seus parâmetros locais:

   ```bash
   # Cortex configuration
   cp cortex/infrastructure/.env.example cortex/infrastructure/.env

   # Hub configuration
   cp hub/infrastructure/docker/.env.example hub/infrastructure/docker/.env.dev
   ```

3. **Inicie a Infraestrutura e as Aplicações Locais:**
   Fornecemos scripts de orquestração unificados via Turborepo e Skaffold. Você pode executar no modo Podman Compose (`pnpm cortex:up` e `pnpm hub:dev`) ou no modo Kubernetes (`pnpm minikube:up` e `pnpm k8s:dev`).
   Consulte [MONOREPO.readme.md](https://github.com/workspace/workspace/blob/develop/MONOREPO.readme.md) ou a [Referência de Comandos](./reference/commands.mdx) para obter detalhes.

## 7. Diátaxis Framework

Uma abordagem sistemática para a criação de documentação técnica.

Diátaxis é uma forma de pensar e fazer documentação.

Ela prescreve abordagens para o conteúdo, arquitetura e formato que emergem de uma abordagem sistemática para entender as necessidades dos usuários da documentação.

O Diátaxis identifica quatro necessidades distintas e quatro formas correspondentes de documentação — _tutoriais_, _guias práticos_ (how-to guides), _referência técnica_ e _explicação_. Ele os coloca em uma relação sistemática e propõe que a documentação deve ser organizada em torno das estruturas dessas necessidades.

O Diátaxis resolve problemas relacionados ao _conteúdo_ da documentação (o que escrever), ao _estilo_ (como escrever) e à _arquitetura_ (como organizar).

Além de atender aos usuários da documentação, o Diátaxis tem valor para os criadores e mantenedores da documentação. Ele é leve, fácil de compreender e simples de aplicar. Ele não impõe restrições de implementação. Ele traz um princípio ativo de qualidade para a documentação que ajuda os mantenedores a pensarem de forma eficaz sobre seu próprio trabalho.
