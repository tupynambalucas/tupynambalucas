### Infraestrutura de Workspace Autohospedada

O projeto `%PROJECT_DOMAIN%` executa uma série de serviços em camadas autohospedados configurados em `studio/design/infrastructure/docker/compose.yaml` para garantir soberania absoluta de dados, colaboração e pipelines de design para código automatizados.

---

## 1. Sistema de Design Penpot e Assistente Aide

O `%PROJECT_DOMAIN%` utiliza uma stack distribuída do Penpot integrada ao Aide, um assistente de engenharia nativo de IA.

### A. Arquitetura de Infraestrutura

O ambiente do Penpot é orquestrado por meio de uma stack Docker multi-container, utilizando backends baseados em nuvem para durabilidade.

* **Orquestração:** Gerenciada por `studio/design/infrastructure/docker/compose.yaml` (Frontend, Backend, Exporter, Valkey, Aide).
* **Camada de Banco de Dados:** Persistência em PostgreSQL hospedada no Neon.tech para integridade transacional sem servidor.
* **Armazenamento de Objetos:** Ativos binários são persistidos em buckets do Cloudflare R2 compatíveis com S3, garantindo um footprint mínimo no Git. Consulte as especificações de [Armazenamento Cloudflare R2](/workspaces/studio/reference/spec/cloudflare-storage).

### B. Aide: Integração Nativa de IA

O Aide funciona como uma ponte do Model Context Protocol (MCP), permitindo que agentes de IA interajam diretamente com a API de Plugins do Penpot para consultas avançadas e transformações de layout.

* **Protocolo:** Comunicação WebSocket bidirecional entre o servidor `@penpot/mcp` e o ambiente do Penpot.
* **Segurança:** O Aide opera dentro da rede isolada `penpot-net`, fornecendo um gateway controlado para manipulação de design.
* **Conectividade:** Utiliza a Porta 4402 para auditorias de design em tempo real e sincronização.

### C. Scripts Operacionais

A ponte do assistente de IA (Aide) é integrada diretamente na stack de orquestração principal do Docker. Execute `pnpm penpot:up` para iniciar toda a plataforma, incluindo o gateway do assistente.

| Comando            | Responsabilidade Técnica                                                       |
| :----------------- | :----------------------------------------------------------------------------- |
| `pnpm penpot:up`   | Inicializa os serviços do editor Penpot e a ponte do Aide em `localhost:9005`. |
| `pnpm penpot:down` | Encerra todos os containers do editor Penpot e auxiliares do Aide.             |

### D. Regras Obrigatórias de Manipulação por IA

* **Reutilização de Componentes:** Verifique sempre a biblioteca de componentes existente (Penpot) ou a biblioteca de UI (`hub/services/web/src/components`) antes de criar novos elementos. O Aide deve priorizar os tokens e componentes do sistema de design existente.
* **Lógica Centrada em Tokens:** As exportações de design para código devem utilizar estritamente Propriedades Personalizadas CSS derivadas de `assets/tokens/` para cores, fontes e espaçamento.
* **Otimização de SVG:** Garanta que o código SVG exportado esteja otimizado, siga os padrões de ícones do projeto e seja integrado por meio do registro `@repo/studio/assets/icons`.
* **Hierarquia de Camadas:** A manutenção do agrupamento semântico é obrigatória. Os elementos devem ser organizados em páginas e frames claros (por exemplo, `Layout/Grid`, `Components/Buttons`).

## 2. Notas Colaborativas do Memos

O Memos é um hub de notas de código aberto e autohospedado que serve como nosso quadro branco colaborativo e centro de compartilhamento de conhecimento para inspirações de design.

### A. Arquitetura de Infraestrutura

O serviço Memos é integrado como um serviço em camadas leve executado dentro do Docker:

* **Orquestração:** Executado no Docker por meio da definição de serviço `memos` dentro de `studio/design/infrastructure/docker/compose.yaml`.
* **Camada de Banco de Dados:** Configurado para usar um banco de dados sem servidor PostgreSQL dedicado hospedado no Neon.tech.
* **Armazenamento de Arquivos Local:** Uploads de imagens, backups e configurações são armazenados localmente dentro de `studio/design/memos/data` (que mapeia para `/var/opt/memos` dentro do container).

### B. Credenciais de Conexão

O Memos acessa o banco de dados usando a string de conexão definida nas variáveis de ambiente:

```env
MEMOS_DRIVER=postgres
MEMOS_DSN=postgresql://your_db_user:your_db_password@your_db_host/your_db_name?sslmode=require
```

### C. Script Operacional

O Memos é iniciado automaticamente junto com o Penpot ao executar o comando da stack do compose:

```bash
pnpm penpot:up
```

Acesse a interface web do Memos localmente em `http://localhost:5230`.
