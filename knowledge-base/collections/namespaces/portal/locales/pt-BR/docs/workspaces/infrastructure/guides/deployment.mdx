# Como Fazer Deploy

Este guia descreve as sequências de comandos de deploy para lançar o ecossistema `%PROJECT_DOMAIN%` em ambientes locais e de produção usando **Skaffold** e **Kubernetes**.

---

## 1. Ambientes Kubernetes (Skaffold)

Os deploys em todos os contextos delimitados (`platform`, `cortex`, `studio`) são gerenciados via Skaffold, orquestrando as fases de build, tag e deploy usando manifests do Kustomize.

### 1.1. Deploys Únicos

Para compilar todas as imagens do workspace e aplicar seus manifests do Kubernetes diretamente ao contexto do cluster ativo sem hot-reloading:

```bash
pnpm infra:up
```

Isso constrói os containers usando o cache do engine local, hidrata as tags de imagem dentro dos manifests e os aplica ao cluster.

### 1.2. Desenvolvimento Contínuo (Live Reload)

Para testes ativos no cluster com logs em tempo real e redeploys automáticos quando o código-fonte for alterado:

```bash
pnpm infra:dev
```

### 1.3. Encerrando Deploys do Cluster

Para excluir todos os recursos com deploy realizado e alocações de namespace do cluster:

```bash
pnpm infra:clean
```

---

## 2. Deploys de Produção

Para ambientes de produção, utilize os overlays do Kustomize localizados em `infrastructure/environments/prod`.

1. Garanta que o seu contexto `kubectl` aponte para o seu cluster de produção.
2. Aplique os overlays de produção diretamente (ou via um operador de GitOps como ArgoCD/Flux):

```bash
kubectl apply -k infrastructure/environments/prod/platform
kubectl apply -k infrastructure/environments/prod/cortex
kubectl apply -k infrastructure/environments/prod/studio
```

*Nota: Para produção, as imagens devem ser pré-construídas e enviadas para um registry remoto (por exemplo, via GitHub Actions) antes de aplicar os manifests, em vez de construí-las localmente com o Skaffold.*
