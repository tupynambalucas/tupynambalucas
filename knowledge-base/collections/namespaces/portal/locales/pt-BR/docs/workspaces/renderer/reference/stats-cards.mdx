O gerador compila cartões visuais SVG personalizados que representam estatísticas de desenvolvedores, distribuição de linguagens e cabeçalhos de marca com absoluta fidelidade visual.

---

## Cartões Visuais Gerados

### 1. Cartão de Visão Geral (`overview.svg`)

Exibe contagens de métricas agregadas (Estrelas, Forks, Contribuições de Todos os Tempos, Linhas de Código Alteradas, Visualizações e Repositórios com Contribuições). Ele utiliza um loop de atraso de animação CSS onde cada linha é animada sequencialmente com um atraso incremental (`(row_index + 1) * 150` ms).

### 2. Cartão de Linguagens (`languages.svg`)

Exibe porcentagens de linguagens ordenadas decrescentemente por tamanho de arquivo.

* **Barra de Progresso**: Acumula tamanhos para exibir uma barra multicolorida. A porcentagem de largura é formatada para exatamente 3 casas decimais na marcação do template.
* **Itens da Lista**: Marcadores de lista individuais contendo nome, cor hexadecimal e porcentagem formatada para exatamente 2 casas decimais.

### 3. Cartão de Cabeçalho (`header.svg`)

Um banner de cabeçalho de marca com estilo personalizado. Ele carrega design tokens de marca e codifica dinamicamente o binário da fonte de marca variável Nunito, incorporando-o como uma string codificada em Base64 dentro da saída vetorial. Isso permite que a tipografia com estilo personalizado seja exibida de forma consistente dentro do sandbox restrito do GitHub.

## Arquitetura de Busca de Dados

Para computar essas métricas, o motor em TypeScript se comunica com o GitHub por meio de GraphQL e REST.

### Estratégia de Subdivisão Anual em GraphQL

Devido ao limite da API do GitHub de 100 repositórios retornados por requisição, uma estratégia de divisão recursiva é aplicada:

* O motor busca repositórios e contribuições ano a ano.
* Se uma consulta retornar exatamente 100 repositórios, o intervalo é dividido por fatores primos (2 ou 3) em sub-intervalos (por exemplo, blocos de 6 meses ou 3 meses).
* Esses sub-intervalos são consultados recursivamente até que a resposta fique abaixo do limite de 100 repositórios, evitando a omissão de dados.

### Resiliência de Conexão e Loop de Repetição da API

Ao contrário das soluções legadas, o motor de renderização moderno apresenta proteção robusta de rede:

* **Exponential Backoff**: Se o GitHub estiver compilando estatísticas ou limites de taxa forem acionados, o motor aguarda e tenta novamente usando atrasos exponenciais.
* **Até 10 Tentativas**: O motor tenta novamente até 10 vezes em caso de falhas de rede ou de API antes de relatar erros.
* **Proibição de Fallbacks com Git Clone**: Operações locais de git-clone são estritamente proibidas dentro do pacote renderer para garantir tarefas de CI/CD leves e evitar o inchaço de ambientes de build. Todos os dados são coletados exclusivamente por meio de conexões de API diretas e seguras.
