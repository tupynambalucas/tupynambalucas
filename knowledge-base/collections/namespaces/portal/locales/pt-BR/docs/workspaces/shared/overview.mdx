O Workspace Shared atua como a configuração global e fundamental e biblioteca de utilitários entre contextos do monorepo %PROJECT_DOMAIN%. Ele abriga metadados centralizados, regras de formatação globais e configurações de ciclo de vida padrão do Git projetadas para serem importadas por qualquer workspace ou pacote downstream dentro do monorepo.

Ao isolar a configuração e os ganchos de ciclo de vida dentro de um workspace shared/ dedicado, prevenimos a divergência de configuração, promovemos a consistência de estilo de código e habilitamos a manutenção descomplicada do monorepo.

## Estrutura de diretórios

`shared/
├── config/              # Centralized configuration assets
│   ├── prettierrc.json  # Base Prettier settings
│   ├── .prettierignore  # Base Prettier ignore rules
│   ├── tsconfig.base.json # Shared base TypeScript compilation rules
│   ├── project.config.json # Single source of truth for project domains
│   └── package.json     # Configuration package (@monorepo/shared-config)
└── git/                 # Centralized Git hooks and scripts
    ├── husky/           # Global git hooks definitions
    ├── scripts/         # Hook execution scripts in TypeScript
    └── package.json     # Git hooks package (@monorepo/shared-git)`

## Pacotes principais

### @monorepo/shared-config (Configurações de projeto centralizadas)

Este pacote centraliza regras de configuração estática e domínios de projeto em todo o monorepo. Em vez de duplicar arquivos de configuração dentro de cada workspace de projeto, o tsconfig.json e as configurações de ferramentas de formatação de cada sub-workspace herdam diretamente deste pacote.

* **Formatação unificada**: A configuração do Prettier (prettierrc.json) e as regras de ignore (.prettierignore) residem aqui, garantindo paridade de estilo perfeita a partir de um único local.
* **TSConfig base**: As configurações base do TypeScript (tsconfig.base.json) estabelecem parâmetros estritos de verificação de tipos e resoluções de módulos para todos os subprocessos.
* **Domínios de projeto**: O arquivo project.config.json serve como a Única Fonte da Verdade (SSOT) para variáveis dinâmicas como %PROJECT_DOMAIN%, que são consumidas durante a compilação de Markdown e o runtime da aplicação.

### @monorepo/shared-git (Ganchos do Git centralizados)

Este pacote abriga nossas barreiras de proteção de controle de versão.

* **Integração com o Husky**: Contém os mapeamentos principais dentro do diretório husky/ para eventos padrão do ciclo de vida do Git (por exemplo, pre-commit, prepare-commit-msg).
* **Scripts multiplataforma**: Define todos os scripts de execução em TypeScript dentro de scripts/, em vez de Bash, garantindo operações consistentes nos ambientes de desenvolvedor Windows, macOS e Linux.

## Gerenciamento de workspaces

As configurações dentro do workspace Shared são consumidas nos níveis raiz e de pacotes. Por exemplo, o package.json raiz coordena a herança de ferramentas e utiliza @monorepo/shared-config para padronizar o Prettier em todo o ecossistema.

:::info[Regra de dependência fundamental]
Os arquivos dentro de shared/ devem sempre permanecer sem estado, genéricos e isolados de lógica de negócios específica ou implementações de backend. Este contexto atua puramente como a base de infraestrutura para ergonomia do desenvolvedor e controle de versão.
:::
