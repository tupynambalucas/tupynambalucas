# Crowdin L10n Configuration Guide

This document defines the strict configuration parameters that must be set in the Crowdin UI to ensure the AI translates the monorepo's MDX documentation with maximum fidelity and minimum QA noise.

## 1. Project Context & Description

Since the translation pipeline relies on Crowdin's AI, the `Project Description` field is injected directly into the LLM's system prompt. Because this monorepo will host multiple documentation namespaces (e.g., `portal`, and future internal services in `knowledge-base/docusaurus/services`), the description must be globally applicable.

### Recommended Project Description

Copy and paste the following English text into **Settings > General > Description**:

```text
[Product Domain & Purpose]
This is the central Knowledge Base and Engineering Portal for a modern TypeScript/Node.js enterprise monorepo. It contains architectural guides, API references, tutorials, and engineering blogs. The content is authored in MDX (Markdown + React JSX).

[Target Audience]
The audience consists of Senior Software Engineers, DevOps Professionals, and Technical Architects.

[AI Persona & Tone of Voice]
Act as an Expert Technical Translator. Maintain a highly professional, objective, and senior engineering tone. The language must be precise and formal. Do not use conversational, playful, or casual phrasing.

[Strict Translation Constraints]
1. Code Preservation: NEVER translate terminal commands, code blocks, file paths, URLs, or Git branch names.
2. MDX Fidelity: NEVER translate React component tags (e.g., <DocCardList />), JSX attributes (e.g., href, className), or frontmatter keys.
3. Technical Jargon: Industry-standard English terms MUST remain in English (e.g., "monorepo", "framework", "deploy", "pipeline", "backend", "frontend", "pull request"). Do not attempt to localize universally accepted developer terminology.
```

## 2. QA Checks & Spellchecker Strategy

Because the documentation is authored in `.mdx` format, the text is heavily interleaved with JSX attributes, technical terms, and CLI commands.

### The Problem

If the standard Crowdin Spellchecker is left fully active, it will flag hundreds of false-positive errors (e.g., `href`, `className`, `scripts`, `docusaurus`, `pnpm`) because they do not exist in standard Brazilian Portuguese (`pt-BR`) dictionaries.

### The Recommendation: Disable Standard Spellchecker

For a developer-focused documentation portal, the noise generated by the standard spellchecker outweighs its benefits.

1. Navigate to **Settings > QA Checks** in Crowdin.
2. Locate the **Spelling** module.
3. **Disable it** (uncheck).

_Why?_ This allows the AI and human reviewers to focus exclusively on critical structural QA warnings (like broken MDX tags, missing translation strings, or broken markdown links) rather than fighting the dictionary over valid technical jargon.

## 3. Style Guide & Tone (pt-BR)

To resolve the "No style guide connected" warning and ensure absolute consistency in the Portuguese translations, you must create a Style Guide in Crowdin. This prevents the AI from mixing "você" and "tu", or switching between formal and informal tones.

### Recommended Style Guide Content

Create a new Style Guide in Crowdin and paste this text to enforce the grammatical rules for Brazilian Portuguese:

```text
[Tone & Voice]
- Voice: Authoritative, senior, and objective.
- Register: Formal but accessible. Always address the user as "você" (never use "tu").

[Grammar & Instructions]
- Imperative Form: When giving instructions, use the formal imperative third-person singular (e.g., "Configure o servidor", "Instale o pacote"). NEVER use the infinitive (e.g., "Configurar o servidor") or the informal imperative (e.g., "Configura o servidor").
- Pronouns: Drop unnecessary personal pronouns. (e.g., "We recommend" -> "Recomendamos", instead of "Nós recomendamos").

[Formatting]
- Technologies: Always capitalize proper nouns and technologies (e.g., React, Node.js, Docusaurus).
- Punctuation: Keep lists and bullet points aligned with the English source punctuation.

[Target Language Neutrality]
- Avoid regional Brazilian slang or idioms. Keep the Portuguese neutral and universally understood in corporate environments.
```

## 4. Translation Memory (TM) & Auto-Approve

Because multiple services will share similar technical terms (e.g., "Prerequisites", "Installation", "Getting Started"), ensure that the Translation Memory is globally enabled across all project files.

- **Pre-translation**: Enable AI pre-translation using TM matches first to save AI credits.
- **Auto-Approve**: Since the workflow is now fully Git-based (`chore/l10n-sync`), any direct edits made by developers in the GitHub Pull Request will sync back to Crowdin. Ensure the GitHub Integration has the **"Approve added translations"** checkbox marked so developer overrides become the new absolute source of truth.
