# Plano de Ação V2: Máxima Simplificação do docusaurus.config.ts## ObjetivoMover a configuração de plugins e o hemeConfig (comoavbar, ooter, e propriedades globais) para dentro do nosso preset local em docs/preset. Migrar todos os arquivos JS/MJS para TypeScript e garantir que o preset incorpore as regras de negócios, reduzindo o boilerplate do arquivo de configuração principal. Além disso, estenderemos o remark plugin para processar páginas estáticas.## Etapas de Execução### 1. Extensão do Remark Plugin para Pages- O Docusaurus permite  emarkPlugins no @docusaurus/plugin-content-pages.- No docs/preset/index.ts, vamos injetar automaticamente o  emark-project-variables não apenas em docs, log,  oadmap e workspaces, **mas também na configuração de pages**. Isso garantirá que arquivos como docs/src/pages/index.tsx (se usarem MDX) ou .md na pasta pages consigam renderizar as variáveis globais %PROJECT_DOMAIN%.### 2. Migração de Diretórios e TypeScript- Mover a pasta docs/plugins inteira para o escopo do preset (docs/preset/plugins).- Converter docs/plugins/remark-project-variables/index.mjs para docs/preset/plugins/remark-project-variables.ts.- Converter docs/plugins/studio-assets/index.ts para docs/preset/plugins/studio-assets.ts.### 3. Extração do ThemeConfig (Navbar & Footer)- Docusaurus não injeta hemeConfig diretamente pelo preset, mas nós podemos compor as propriedades.- Criaremos um arquivo docs/preset/themeConfig.ts que exportará uma função getBaseThemeConfig(projectConfig).- Esse arquivo abstrairá toda a lógica gigante do  avbar, ooter, prism e colorMode.- O docusaurus.config.ts importará essa função, permitindo sobrescritas apenas se necessário:  ` s  import { getBaseThemeConfig } from './preset/themeConfig';  const config: Config = {  // ... configurações curtas ...  themeConfig: getBaseThemeConfig(projectConfig),  };  `### 4. Atualização das Opções do Preset (docs/preset/options.ts & index.ts)- Estender MonorepoPresetOptions para suportar  oadmap e workspaces nativamente.- Injetar o plugin de assets studio-assets.ts nativamente pelo array de plugins do preset.### 5. Limpeza Final do docs/docusaurus.config.ts- Remoção total da diretiva plugins: [...] e imports manuais de projectVariablesPlugin.- Remoção de dezenas de linhas referentes ao  avbar e ooter.- O arquivo final ficará incrivelmente enxuto, focado na declaração das metadatas macro do site (title, url, tagline) e delegando todo o ecossistema interno para a pasta preset.### 6. Homologação e TestesApós as refatorações e migração para TypeScript, é estritamente obrigatório validar a configuração rodando na raiz do monorepo:1. pnpm docs:dev: Para garantir que o servidor de desenvolvimento e o _hot-reload_ sobem sem erros de compilação ou de rotas.2. pnpm docs:build: Para assegurar que o build de produção (SSR) ocorra corretamente, processando o Webpack e confirmando que o Docusaurus consegue instanciar todos os presets e plugins sem falhas de SSR/Node.
