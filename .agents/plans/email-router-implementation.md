# Execution Plan: Email Router & Auto-Reply Architecture## 1. Visão Geral da ArquiteturaEsta implementação estabelece um sistema de roteamento de e-mails via Cloudflare Workers, utilizando o Resend para envio de respostas automáticas. A arquitetura respeita os _Bounded Contexts_ do monorepo, separando o design (templates) da infraestrutura (worker).## 2. Estratégia de Hospedagem da LogoPara inserir a logo em e-mails HTML, **nunca** devemos usar Base64 (causa bloqueios e aumenta o peso do e-mail). A estratégia ideal, alinhada à sua infraestrutura atual, é:1. **Hospedagem em Cloudflare R2:** Como você já utiliza R2 para o Penpot e Memos, podemos criar um bucket público (ex: cdn.tupynambalucas.dev) dedicado aos _assets_ da marca (studio).2. **Alternativa Direta:** Referenciar a logo diretamente dos arquivos estáticos do seu frontend principal (https://tupynambalucas.dev/logo.png).3. No template HTML (gerado pelo   enderer), a logo será referenciada por uma URL absoluta via tag <img>, garantindo carregamento instantâneo e renderização perfeita em clientes como Gmail e Apple Mail.## 3. Estrutura de DiretóriosO código será dividido em dois contextos:### A. O Motor de Templates (Design/Renderização)**Local:** \enderer/src/emails/\- **Responsabilidade:** Manter os templates HTML/CSS ou React Email.- **Motivo:** O \  enderer\ é o responsável natural pela geração de _assets_ dinâmicos e marcação. O worker apenas consumirá a string final exportada por este pacote.### B. O Worker de Roteamento (Infraestrutura/Edge)**Local:** \platform/workers/email-router/\- **Responsabilidade:** Receber o gatilho (trigger) do Cloudflare Email Routing, executar a lógica de validação (anti-loop) e disparar a API do Resend.- **Motivo:** O contexto \platform\ gerencia a infraestrutura de borda (Edge) e integrações diretas com o painel da Cloudflare.## 4. Passos de Implementação (Step-by-Step)### Passo 1: Publicação dos Assets Visuais- Garantir que a versão correta da logo (dark/light, dimensionada) esteja disponível publicamente via URL HTTPS (ex: Cloudflare R2 ou pasta pública do site).### Passo 2: Construção do Template no Renderer- Criar o arquivo do template no \  enderer\ (ex: \  enderer/src/emails/ContactAutoReply.ts\).- Construir o HTML injetando a URL da logo na tag \<img src="..." width="120" />\.- Exportar uma função que retorna a string HTML pura.### Passo 3: Criação do Cloudflare Worker- Inicializar o projeto em \platform/workers/email-router\.- Criar o \wrangler.toml\ básico (sem subir a API Key no código).- Codificar o \src/index.ts\ para lidar com o evento \mail\, importando o template gerado pelo \  enderer\.### Passo 4: Gerenciamento de Segredos- Registrar \RESEND_API_KEY\ diretamente na Cloudflare via comando:  \  px wrangler secret put RESEND_API_KEY\### Passo 5: CI/CD Pipeline- Criar \.github/workflows/deploy-email-worker.yml\.- Adicionar _step_ para fazer o \uild\ do pacote \  enderer\ (se necessário).- Adicionar _step_ usando \cloudflare/wrangler-action@v3\ para fazer o deploy do código localizado em \platform/workers/email-router\.
